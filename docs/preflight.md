# Local System Check · Automatic Configuration

> Since 0.5.8, the settings page has a "Start check": it first works out whether this machine can run, and what needs changing.
> Anything that can be changed automatically is changed; anything that needs elevation gets a button; anything that can only be changed in the BIOS is explained clearly.

## 1. What is checked

| Item | How it is checked | When it cannot be determined |
|---|---|---|
| CPU virtualization (VT-x / SVM) | `VirtualizationFirmwareEnabled` / `VMMonitorModeExtensions` of `Win32_Processor` | Recorded as "unknown", with a prompt to confirm manually |
| Whether Hyper-V / VBS is running | `Win32_ComputerSystem.HypervisorPresent` | Unknown |
| Hypervisor Platform (WHPX) | `Get-WindowsOptionalFeature -FeatureName HypervisorPlatform`; without permission, falls back to whether `WinHvPlatform.dll` + Hypervisor are present | Unknown (treating it as "available" requires both pieces of evidence) |
| Whether hardware acceleration is currently available | `emulator -accel-check` (reuses the provisioner's cached result) | Treated as unavailable |
| AEHD driver | `%SystemRoot%\System32\drivers\aehd.sys` | Treated as not installed |
| GPU / VRAM / driver version | `Win32_VideoController` + registry `HardwareInformation.qwMemorySize` (`AdapterRAM` is truncated above 4GB and unreliable) | GPU unknown |
| Memory / OS version | `Win32_ComputerSystem`, `os.release()` | — |

**The WMI pitfall**: once Hyper-V / memory integrity (VBS) takes over VT, `VMMonitorModeExtensions` and `SecondLevelAddressTranslationExtensions` return `False` — even though the machine can clearly run hardware acceleration. So when these two fields are `False`, "no virtualization support" is only concluded if there is "no hypervisor and acceleration is also unavailable"; otherwise it is always treated as unknown. Otherwise a perfectly good machine would be wrongly judged unable to run.

## 2. What is changed automatically

After the check completes, click "Apply recommended configuration". Only these items are written (all safe entries, changeable again at any time in settings):

| Setting | Rule |
|---|---|
| `memoryMB` | 32GB host → 8GB; 16GB → 6GB; 12GB → 4GB; 8GB → 3GB; smaller → 2GB. And never more than half the host |
| `cores` | 8+ threads → 4 cores; 4~7 → 2~3 cores; always leave at least 1 core for Windows |
| `renderSize` | No hardware acceleration, or VRAM <512MB → `540x960`; otherwise `auto` |
| `gpuMode` | With acceleration `auto` (handed to the fallback chain); without acceleration → `software` |
| `forceTcg` | No hardware acceleration → `true` |

At the same time, this machine's parameters are frozen into a driver (`%APPDATA%\hydra\drivers\auto-<vendor>-<build>.json`, `priority: 5`), applied automatically on every subsequent boot, so the check does not need to be repeated. Drivers must also pass whitelist validation — even content generated by the check cannot bypass the parameter limits.

## 3. What requires user involvement

| Situation | What the UI offers |
|---|---|
| VT-x / SVM not enabled in BIOS | **Manual guidance only** (restart into BIOS → Intel VT-x / SVM Mode → Enabled). This step physically cannot be done on the user's behalf |
| Windows feature not enabled (installer version) | "Enable with one click (requires admin)" → elevates to run `dism` to enable HypervisorPlatform + VirtualMachinePlatform → prompts for restart |
| Windows feature not enabled (Microsoft Store version) | "Open the 'Windows features' window" — MSIX is fixed at mediumIL and cannot self-elevate, so only the entry point and checkboxes are provided |
| No acceleration and CPU supports virtualization (installer version) | Additionally offers "Install AEHD driver (requires admin)" |
| GPU driver too old (>3 years) | Only reminds the user to update from the vendor's website; does not install drivers automatically (installing the wrong version is worse) |

## 4. Conclusion levels

- `ok`: this item is fine;
- `warn`: usable, but improvement is recommended (memory too small, driver out of date, OS version too old, hardware information unreadable);
- `bad`: will not run without action (virtualization not enabled in BIOS, Windows feature not enabled).

The overall check level is the worst item; the UI shows a colored dot and a specific explanation for each entry, never "unknown error".

## 5. Privacy

All probing is done locally: it only reads WMI / the registry / whether system files exist, and sends no requests or uploads any information. The exported diagnostic report also contains only the fields needed for troubleshooting, such as model, driver version, and memory.
